# Development Phases

This document outlines the detailed roadmap for bringing the AI Employee OS from its current boilerplate state to a production-ready system.

## Phase 1: Environment & Authentication Foundation
**Objective:** Establish a stable development environment and successfully integrate the frontend, backend, and Supabase database using a unified authentication model.

**Deliverables:**
- Corrected backend `requirements.txt` (installing FastAPI, SQLAlchemy, python-jose, psycopg2).
- Cleaned backend configuration (`database.py` secrets removed, CORS configured).
- Implementation of the `get_current_user` dependency in FastAPI to validate Supabase JWTs.
- Basic frontend login and registration pages wired to Supabase Auth.
- Backend `/api/v1/auth/me` endpoint functioning and returning the user's profile.

**Dependencies:** None.
**Estimated Effort:** 2-3 Days.
**Definition of Done:** A user can register on the frontend, log in, and the frontend can successfully call a protected backend endpoint using the session JWT.

## Phase 2: Core Data Access & Alignment
**Objective:** Ensure the backend SQLAlchemy models accurately reflect the current 71-table Supabase schema.

**Deliverables:**
- Refactored `User`, `Organization`, and `AI_Employee` models to match migrations (e.g., removing `password_hash`).
- Basic CRUD endpoints for Organizations and Users under `/api/v1/organizations` and `/api/v1/users`.
- Implementation of the tenant-isolation middleware in FastAPI to automatically scope database sessions to the `current_org_id`.

**Dependencies:** Phase 1.
**Estimated Effort:** 3-5 Days.
**Definition of Done:** The backend can read and write to the database using SQLAlchemy without schema mismatch errors, and tenant isolation is strictly enforced.

## Phase 3: AI Chat MVP (Vertical Slice)
**Objective:** Deliver the core value proposition — the ability to chat with an AI Employee.

**Deliverables:**
- Implementation of `ai/model_router.py` to communicate with OpenRouter.
- Implementation of the core `ai/engine.py` orchestrator.
- A basic "Sales Agent" (`sales_agent.py`) with a predefined system prompt.
- Backend routes for `/api/v1/ai-chat/conversations` and `/api/v1/ai-chat/messages`.
- Frontend chat UI component that renders streamed responses.

**Dependencies:** Phase 2.
**Estimated Effort:** 1 Week.
**Definition of Done:** A user can navigate to the AI Chat dashboard, select the Sales Agent, ask a question, and receive a streamed, context-aware response generated by an LLM.

## Phase 4: Business Logic & Dashboards (CRM, Finance, HR)
**Objective:** Build out the traditional SaaS modules to give the AI Agents data to interact with.

**Deliverables:**
- SQLAlchemy models and CRUD endpoints for CRM (Leads, Pipelines), Finance (Invoices, Quotations), and HR (Employees).
- Frontend dashboards displaying this data using tables and charts.

**Dependencies:** Phase 2.
**Estimated Effort:** 2-3 Weeks.
**Definition of Done:** Users can manually manage leads, create invoices, and view company metrics through the frontend UI.

## Phase 5: AI Tool Execution & RAG Integration
**Objective:** Empower the AI Employees to read and manipulate the business data, and reference internal documents.

**Deliverables:**
- Implementation of specific AI tools (e.g., `search_crm`, `create_invoice`, `read_document`).
- Agent logic updated to request and process tool executions before answering the user.
- Document upload endpoints, Celery workers for text chunking/embedding, and pgvector search integration.

**Dependencies:** Phase 3 & Phase 4.
**Estimated Effort:** 2 Weeks.
**Definition of Done:** A user can tell the AI Sales Assistant to "Find all leads from last week and draft an email," and the agent will execute the CRM search tool, read the data, and return a draft.

## Phase 6: Production Hardening
**Objective:** Prepare the application for public launch.

**Deliverables:**
- Global exception handlers and structured request logging.
- API rate limiting (Redis-backed).
- Comprehensive test suite (pytest) covering the core engine and auth flows.
- Dockerization (Dockerfile for FastAPI, docker-compose for local testing).
- CI/CD pipeline setup for automated testing and deployment.

**Dependencies:** Phase 5.
**Estimated Effort:** 1-2 Weeks.
**Definition of Done:** The system passes all automated tests, can be deployed via Docker, and handles errors gracefully without exposing stack traces to the client.
